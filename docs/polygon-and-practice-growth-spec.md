# 폴리곤 기준과 연습 성장 지표 사양

**상태:** 구현 전 기준 사양  
**작성일:** 2026-08-21  
**대상:** 폴리곤 메트로놈, 활동 기록, Work Up 통계, 연습장/백업

이 문서는 현재 폴리곤이 사용하는 “한 마디를 N등분” 동작과 활동 로그의
시간·BPM 기록을 보존하면서, 이후 기준 선택과 성장 지표를 추가할 때의 계약을
정한다. 이 문서 자체는 UI, 통계 화면, 자동 채점 엔진을 추가하지 않는다.

## 1. 결정 요약

1. **기본 폴리곤 주기는 한 마디다.** `N`각형은 한 마디 안에서 N번 등간격으로
   발화한다. 이는 현재 동작과 완전히 호환되는 기본값이다.
2. 이후 선택지는 한 레이어의 “N”을 바꾸는 것이 아니라, **주기 범위**와
   **기준 펄스**를 명시한다. 따라서 “3:4”는 모호한 라벨이 아니라
   “한 4/4 마디에 3회, 4분음표 기준 박 4회”처럼 표시한다.
3. **6/8은 복합박을 우선 해석**한다. 기본 박은 점4분음표 2개이고, 사용자는
   8분음표 6개 기준으로 바꿀 수 있다. 두 해석 모두 유효하며 이름과 시각
   묶음이 달라야 한다.
4. 스윙은 범용 지연값이 아니라 **동일한 기준 펄스 안의 짝수 분할 쌍**에
   적용한다. 꼭짓점 수동 오프셋은 스윙보다 높은 우선순위를 갖는다.
5. 성장 지표는 기록 동의를 켠 사용자의 **능동 재생 시간**만 다룬다. 원본
   오디오, 위치 좌표, 마이크 신호, 개인식별정보는 성장 지표에 저장하지 않는다.
6. 자동 채점 엔진이 없는 동안 “정확도”는 사용자 연주 정확도가 아니다. 화면에는
   “측정 불가”로 두며, 엔진 실행의 안정성과 반복 완수만 별도 지표로 표시한다.

## 2. 폴리곤 음악 모델

### 2.1 용어

| 용어 | 뜻 | 현재 구현과의 관계 |
|---|---|---|
| **마디 주기 (measure cycle)** | 박자표가 정의한 한 마디 전체 길이 | 현재의 유일한 주기 |
| **기준 펄스 (reference pulse)** | 사용자가 체감/연습 기준으로 삼는 단위. 예: 4분음표, 점4분음표 | 신규 메타데이터 |
| **기준 음표 (reference note)** | 기준 펄스의 표기 음가 | 신규 메타데이터 |
| **분할 (division)** | 주기 안에 균등하게 놓이는 이벤트 수 | 기존 `sides` |
| **레이어** | 서로 다른 분할·사운드·강세를 겹치는 하나의 폴리곤 | 기존 `PolygonLayer` |
| **강세** | strong/accent/normal/mute의 음색·시각 강조 | 기존 `beatTypes` |
| **스윙** | 동등한 두 분할을 long–short 비율로 재배치하는 연주 해석 | 기존 꼭짓점 오프셋과 구별 |
| **수동 오프셋** | 한 꼭짓점만 의도적으로 앞/뒤로 이동하는 미세 조정 | 기존 `offsets` |

### 2.2 범위와 기준 음표

각 폴리곤 프리셋은 다음을 보유한다. 레이어 고유 필드로 만들기보다 프리셋/세션
공통 설정으로 두는 것을 권고한다. 함께 연습하는 레이어가 서로 다른 “한 마디”를
뜻하면 사용자가 관계를 해석할 수 없기 때문이다.

```ts
type PolygonCycleScope = "measure" | "reference_pulse";
type ReferenceNote = "meter_denominator" | "dotted_meter_unit" | "quarter";
type SwingRatio = "straight" | "2:1" | "3:2";

interface PolygonTimingBasis {
  cycleScope: PolygonCycleScope;    // 기본: "measure"
  referenceNote: ReferenceNote;     // 기본: 박자표에 따른 자동 선택
  swing: SwingRatio;                // 기본: "straight"
}
```

- `measure`: 레이어의 N개 이벤트를 **한 마디 길이**에 균등 배치한다.
- `reference_pulse`: N개 이벤트를 기준 펄스 하나에 균등 배치하고, 마디 안의
  각 기준 펄스마다 반복한다.
- `meter_denominator`: 4/4에서는 4분음표, 3/4에서는 4분음표, 6/8에서는
  8분음표다.
- `dotted_meter_unit`: 복합박일 때만 선택 가능하며 6/8·9/8·12/8에서 각각
  점4분음표다. 단순박에서는 표시하지 않는다.
- `quarter`: 서로 다른 박자표/복합박을 비교하는 고급 모드다. BPM과 표기 단위를
  명확히 함께 표시해야 한다.

### 2.3 기본값과 해석 우선순위

1. 사용자가 저장한 `PolygonTimingBasis`
2. 새 프리셋의 박자표 기반 기본값
3. 레이어의 N 분할
4. 스윙 규칙
5. 꼭짓점의 수동 오프셋
6. 꼭짓점 강세/뮤트(시간 위치는 바꾸지 않음)

기본값은 다음과 같다.

| 박자표 | 기본 범위 | 기본 기준 펄스 | 화면의 그룹 표시 |
|---|---|---|---|
| 2/4, 3/4, 4/4, 5/4 | 한 마디 | 분모 음표 | 매 박자 |
| 6/8 | 한 마디 | 점4분음표 | `3 + 3` 8분음표 묶음 |
| 9/8 | 한 마디 | 점4분음표 | `3 + 3 + 3` |
| 12/8 | 한 마디 | 점4분음표 | `3 + 3 + 3 + 3` |

**수동 오프셋 우선 규칙:** 스윙이 어떤 꼭짓점을 `0.50` 슬롯만큼 늦추려 해도,
그 꼭짓점에 사용자가 오프셋을 지정했다면 수동 오프셋만 적용한다. UI는 해당
꼭짓점에 “수동” 표식을 보여 스윙과의 차이를 설명해야 한다.

### 2.4 스윙 규칙

- `straight`: 모든 분할은 균등하다.
- `2:1`: 기준 펄스 안의 2분할은 `2/3 : 1/3` 위치가 된다.
- `3:2`: 기준 펄스 안의 2분할은 `3/5 : 2/5` 위치가 된다.
- 스윙은 **2분할 쌍이 명확한 경우**에만 적용한다. 3, 5 등 홀수 분할 또는
  기준 펄스를 걸쳐가는 분할에는 적용하지 않고 “이 분할에는 스윙을 적용할 수
  없음”을 표시한다.
- 스윙은 여러 레이어를 정렬하는 공통 시간 해석이다. 한 레이어만 스윙시키려면
  고급 수동 오프셋을 사용하며, 이는 폴리리듬의 균등성도 의도적으로 깨뜨린다.

## 3. 대표 청취·표시 사례

### 3.1 4/4에서 3:4

- 기준: 한 4/4 마디, 4분음표 기준 박.
- 4 레이어는 `0, 1, 2, 3`박에 들린다.
- 3 레이어는 마디 시작, `1⅓`박, `2⅔`박에 들린다.
- 화면: 중앙의 `4/4 · 1 bar` 라벨과 함께 `3 against 4`를 표시한다.
  꼭짓점 세 개와 네 개의 첫 꼭짓점은 같은 1박에 정렬되어야 한다.
- 기대: 3 레이어는 “셋잇단음표”가 아니라 **4분음표 4개 길이에 걸친 3개**다.

### 3.2 4/4에서 5:4

- 기준: 한 4/4 마디.
- 5 레이어는 마디 길이를 5등분하고 4 레이어는 네 박을 유지한다.
- 화면: `5 against 4 · one bar`; 시작 꼭짓점만 동시 발화한다.
- 기대: 5 이벤트가 각 박에 하나씩 붙어 보이거나, 마지막에 남는 방식으로
  반올림되어서는 안 된다.

### 3.3 6/8의 기본 복합박

- 기본 기준: 점4분음표 두 개, 각 펄스는 8분음표 세 개 길이다.
- 2 레이어는 두 개의 점4분음표 펄스에, 3 레이어는 한 마디 전체 3등분에,
  6 레이어는 여섯 8분음표에 맞는다.
- 화면: `6/8 · 2 dotted-quarter pulses (3+3)`를 보이고, 두 큰 묶음 사이에
  강한 구분선을 둔다.
- 사용자가 기준을 `8분음표`로 바꾸면 `6 pulses per bar`로 표기하며, 이는
  같은 실제 길이에 대한 다른 연습 관점이다.

### 3.4 기준 펄스 범위 예시

4/4에서 `reference_pulse + quarter + 3`은 **각 4분음표 안의 3분할**이므로
마디 전체에서 12 이벤트가 난다. `measure + 3`은 한 마디 전체에서 3 이벤트다.
UI는 둘을 같은 “3”으로만 표기하면 안 되며, 각각 `3 per beat`와
`3 per bar`로 표시해야 한다.

## 4. 폴리곤 UI/저장 수용 기준

향후 구현은 다음을 만족해야 한다.

- 모든 재생 화면에 `박자표 · 범위 · 기준 음표 · 스윙`을 짧게 노출한다.
- 프리셋 공유·백업에는 `PolygonTimingBasis`를 포함한다. 필드가 없는 기존
  프리셋은 `measure + meter default + straight`로 읽는다.
- 기준을 바꾸면 재생 중인 마디 중간에 재배열하지 않고 다음 마디에서 적용한다.
- 현재 `offsets` 배열은 계속 지원한다. 새 스윙과 충돌하면 수동 오프셋이 우선임을
  UI와 도움말에 명시한다.
- 6/8 기본값과 3:4/5:4 예시는 단위 테스트의 시간 위치와 스냅샷 테스트의
  라벨로 고정한다.

## 5. 연습 세션 측정 계약

### 5.1 상태 전이

| 사건 | 세션 상태 | 능동 시간 | 새 기록 |
|---|---|---:|---|
| 재생 시작 | `running` | 시작 | 세션 임시 상태 생성 |
| 사용자 일시정지 | `paused` | 멈춤 | pause 구간 추가 |
| 사용자 재개 | `running` | 재개 | pause 구간 종료 |
| OS 인터럽션/오디오 복구 | `interrupted` | 멈춤 | 원인만 기록, 새 세션 아님 |
| 자동/수동 복구 성공 | `running` | 재개 | 중단 구간 제외 |
| 사용자가 정지 | `completed` | 종료 | 조건 충족 시 최종 로그 1개 |
| 타이머·마디 완료 | `completed` | 종료 | 조건 충족 시 최종 로그 1개 |
| 앱 강제 종료/충돌 | `abandoned` | 미확정 | 기본적으로 성장 지표에 제외 |

**최소 기록 단위:** 한 번의 시작부터 종료까지의 세션 요약 하나다. 능동 시간이
3초 미만이면 저장하지 않는다. 일시정지·인터럽션은 별도 연습 세션을 만들지 않으며
능동 시간에서 제외한다. 이는 현재의 3초 미만 세션 무시 규칙과 호환된다.

### 5.2 신규 세션 데이터 계약

```ts
interface PracticeSessionV2 {
  schemaVersion: 2;
  startedAt: number;           // epoch ms, 세션을 연 순간
  endedAt: number;             // epoch ms, 끝난 순간
  activeDurationSec: number;   // 재생/실제 연습으로 인정된 초
  pausedDurationSec: number;   // 표시·디버그용, 성장 시간에는 미포함
  interruptionDurationSec: number; // 오디오 중단으로 제외된 시간
  pauseCount: number;
  interruptionCount: number;
  mode: "dial" | "bar" | "note" | "score" | "polygon";
  bpmStart: number;
  bpmEnd: number;
  bpmPeak: number;
  timingBasis?: PolygonTimingBasis; // polygon일 때만
  meter?: { numerator: number; denominator: 2 | 4 | 8 };
  status: "completed" | "abandoned";
  endReason: "manual" | "timer" | "measure_complete" | "fade_out"
    | "audio_interruption" | "audio_recovery_failed";
  repeatCount?: number;        // 명시적 반복이 끝난 수, 추정 금지
  goalId?: string;             // 연결된 목표가 있을 때만
  quality?: {
    source: "none" | "manual_check" | "future_detector";
    accuracyPct?: number;      // source가 none이면 절대 저장하지 않음
    stabilityMs?: number;      // source가 future_detector일 때만
  };
}
```

`timestamp`는 기존 로그 호환을 위해 최종 저장 시각(보통 `endedAt`)으로 유지한다.
사용자 이름, GPS 좌표, 원본 오디오, 음성 전사, 기기 식별자는 이 계약에 넣지 않는다.

## 6. 성장 지표 정의

| 지표 | 계산식 | 입력 | 표시 | 제한 |
|---|---|---|---|---|
| 능동 연습 시간 | `Σ activeDurationSec` | 완료 세션 | 오늘/주/월 시간 | 중단·일시정지 제외 |
| BPM 성장 | 기간별 자격 세션의 `bpmEnd` 중앙값 차이 | mode·meter·기준이 같은 세션, 각 3개 이상 | `+N BPM` 또는 “데이터 부족” | 다른 패턴·박자표를 섞어 비교 금지 |
| 최고 안정 BPM | 품질 기준을 통과한 세션의 최대 `bpmEnd` | 향후 detector 또는 수동 확인 | 개인 최고 기록 | 현재는 표시하지 않음 |
| 반복 완수 | `Σ repeatCount` | 완료·명시적 반복 세션 | 목표 대비 `x/y회` | 추정 반복, 자동 루프 시간 환산 금지 |
| 목표 달성 | 해당 날짜의 능동 시간/반복이 목표 이상 | Goal + 세션 | 달성/진행률 | 목표 유형과 단위를 표시 |
| 정확도 | `on-time events / evaluated events × 100` | 사용자 연주 detector 이벤트 | %와 표본 수 | 자동 채점 도입 전에는 측정 불가 |
| 안정성 | 이벤트 오차의 중앙절대편차(MAD), ms | 사용자 연주 detector 이벤트 | 낮을수록 안정적 | 마이크·블루투스 지연 보정 없이는 표시 금지 |

### BPM 성장 자격 조건

- 같은 `mode`, 같은 박자표, 같은 폴리곤 `timingBasis`, 같은 연습장 항목(있는 경우)
  안에서만 비교한다.
- 기간마다 3개 이상의 완료 세션, 각 세션 30초 이상의 능동 시간이 필요하다.
- 중앙값을 사용해 한 번의 극단 BPM 조작이 성장으로 보이지 않게 한다.
- 자격 조건을 만족하지 않으면 값 대신 “아직 비교할 연습이 부족합니다”를 표시한다.

### 정확도·안정성의 비표시 원칙

현재 앱은 메트로놈을 재생하지만 사용자의 실제 타격/연주 시점을 수집하지 않는다.
따라서 클릭이 정확히 스케줄된 사실은 사용자의 정확도가 아니다. 새 인식 엔진,
명확한 동의, 입력 지연 보정, 표본 수 안내가 모두 갖춰질 때까지 정확도·안정성
카드는 숨기거나 “측정 기능 준비 중”으로만 보인다.

## 7. 개인정보·보관·시간대

### 7.1 동의와 로컬 보관

- 활동 기록은 기본적으로 꺼져 있다. 사용자가 설정에서 명시적으로 켠 뒤부터
  새 세션을 기록한다.
- 기록은 기기 로컬 저장소에만 보관한다. 계정·클라우드 동기화·광고 추적은
  이 범위에 포함하지 않는다.
- 원본 마이크/오디오 데이터는 저장하지 않는다. 향후 정확도 기능도 기본값은
  집계값만 저장하며, 원본 오디오는 별도 명시 동의 없이는 금지한다.
- 세부 세션은 **730일** 보관한다. 그보다 오래된 세션은 주기적으로 삭제한다.
  장기 추세가 필요해지면 개인을 식별하지 않는 월별 합계만 별도 사양으로
  도입한다.

### 7.2 사용자 제어

- “활동 기록 삭제”는 세션·목표·로컬 집계 캐시를 함께 지운다.
- 기존 백업은 현재 활동 로그와 목표를 포함한다. 신규 V2 필드는 같은 백업
  키 안에 JSON으로 들어가며, 사용자는 백업 파일을 내보내거나 삭제할 수 있다.
- 기록을 끄면 새 세션만 중단한다. 기존 데이터를 자동 삭제하지 않으며,
  삭제 동작은 별도 확인을 요구한다.

### 7.3 시간대

- 원본은 epoch milliseconds로 저장한다.
- 일/주/월 버킷은 **표시 시점의 기기 로컬 시간대**로 계산한다.
- 시간대 변경 전후의 과거 세션은 새 시간대의 날짜로 보일 수 있다. 이 사실을
  날짜별 통계 도움말에 알린다.
- 역사적 날짜를 절대 고정해야 하는 향후 기능이 생기면 IANA time zone을
  세션에 추가하되, 이 사양의 첫 단계에서는 저장하지 않는다.

## 8. 기존 데이터와 마이그레이션

| 기존 필드 | V2 처리 |
|---|---|
| `timestamp` | `endedAt`으로 사용 |
| `duration` | `activeDurationSec`으로 사용 |
| `bpm` | `bpmStart`, `bpmEnd`, `bpmPeak`에 동일 값 복사 |
| `mode: dial/bar` | 그대로 사용 |
| `barConfig`, 연습장 ID/라벨 | 보존 |
| pause, interruption, repeat, quality | `unknown`/미측정으로 둠 |

- 기존 로그를 앱 시작 때 일괄 재작성하지 않는다. 읽을 때 V1을 V2의 최소
  뷰로 해석한다.
- V1 로그는 능동 시간·기존 목표·BPM별 시간 집계에는 쓸 수 있다.
- V1 로그는 BPM 성장, 반복 완수, 정확도, 안정성의 자격 표본으로 쓰지 않는다.
- 백업/공유/연습장 포맷을 바꾸기 전에 명시적인 스키마 버전과 복원 테스트를
  추가한다.

## 9. 단계별 도입 범위

### 단계 A — 데이터 기반 정리

1. `PracticeSessionV2`와 명시적 세션 상태 전이를 도입한다.
2. pause/interruption 제외 시간, 종료 사유, mode/meter를 기록한다.
3. 730일 정리, 전체 삭제, 로깅 동의 UI를 구현한다.
4. 기존 Work Up의 시간·기존 목표 집계가 V1/V2 모두에서 유지되는지 검증한다.

### 단계 B — 폴리곤 기준 선택

1. `PolygonTimingBasis`를 프리셋과 세션에 저장한다.
2. measure/reference-pulse, 기준 음표, 복합박 그룹, 스윙을 표시한다.
3. 3:4, 5:4, 6/8의 예약 시간과 다음 마디 적용 규칙을 자동 테스트한다.
4. 기존 폴리곤 설정은 현재와 같은 한 마디·스트레이트로 읽는다.

### 단계 C — 해석 가능한 성장 화면

1. 자격 조건을 충족한 BPM 성장과 반복 완수만 먼저 공개한다.
2. 비교 조건·표본 수·“데이터 부족” 이유를 화면에 표시한다.
3. 정확도·안정성은 입력 품질 계약이 완성될 때까지 구현/마케팅하지 않는다.

## 10. 구현 수용 기준

- 3:4, 5:4, 6/8 기본 복합박, 6/8 8분음표 기준의 발화 시간과 라벨이 문서의
  정의와 일치한다.
- 스윙은 적격한 2분할에만 적용되고 수동 오프셋이 항상 우선한다.
- pause·인터럽션 구간은 능동 연습 시간과 목표 진행에서 제외된다.
- 3초 미만 세션과 abandoned 세션은 성장 지표를 바꾸지 않는다.
- V1 활동 로그·연습장·백업을 읽어도 기존 시간과 목표가 사라지지 않는다.
- 기록이 꺼진 상태에서는 새 성장 데이터가 저장되지 않는다.
- 정확도/안정성은 실제 입력 데이터와 동의가 없으면 수치로 표시되지 않는다.
