# 리듬 입력 타이밍 보정

## 기준과 적용 범위

- 개인의 듣기·입력 오프셋을 추정한다. 순수 하드웨어 지연 측정이 아니다.
- 출력 준비를 완료하고 웹 AudioContext가 실행 중인 것을 확인한 뒤
  기준음을 예약한다. 각 박은 재생 요청이 수락된 시각에 입력과 같은 단조
  시계로 기록한다. 네이티브 재생 실패는 기준 박으로 인정하지 않는다.
- 이는 스피커/DAC의 물리 발음 시각이 아니다. 네이티브 드라이버·Bluetooth
  지연과 실제 손가락 입력은 별도 기기 확인이 필요하다.
- 예비 4박 후 16박을 측정한다. 기준음 준비 중·예비박 앞부분·완료 후
  탭은 결과를 바꾸지 않는다. 다시 시작·초기화·설정 닫기·화면 전환·앱
  비활성화는 이전 세션을 취소한다.
- 16개 박을 각각 대응시키고 누락·중복·한 박 밀림·불안정한 출력 간격과
  입력 편차를 거부한다. 실패한 보정은 기존 값을 유지한다.

## 부호와 데이터 보존

양수는 늦은 입력을 앞당긴다. 원본 down/up 값은 수정하지 않으며,
기보 시 적용하는 오프셋을 원본 재생에 소급하지 않는다.
원본 따라 치기의 기준과 실제 입력을 비교할 때는 두 쪽을 같은 보정
시간축으로 바꿔야 한다. 이미 보정된 기보 시각에 다시 빼지 않는다.
수동 범위는 −2000…2000ms이며 저장/재열기로 유지한다.
초기화는 화면의 숫자뿐 아니라 문서의 실제 적용값도 0으로 바꾼다.

## 검증과 한계

- 합성 입력 −80/0/+60ms 결과, 40ms 늦은 완전한 측정 패스,
  준비 지연, 초기화/재시작/해제 후 늦은 콜백, 기준음 없는 탭,
  누락·중복·한 박 밀린 탭과 큰 편차를 검사했다.
- 네이티브 오디오 모의 검사에서는 재생 요청 수락 전에는 기준 박을
  기록하지 않고, 재생 실패 시에도 박이 기록되지 않는 것을 확인했다.
  실제 기기에서 소리를 청취했다는 뜻은 아니다.
- 컴포넌트에서 문서/표시값 초기화와 보정 1회 적용 후 연습 점수를
  확인했다. 브라우저에서 수동값 저장/재열기와 기준음 시작/초기화를 확인했다.
- Chromium과 단위 테스트를 사용했다. 실제 iPhone/Android의 물리 출력
  시각, Safari 터치/오디오 정책, 보조기술은 이번 환경에서 확인하지 못했다.
