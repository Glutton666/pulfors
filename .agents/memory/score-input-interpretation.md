description: 직접 연주 입력의 기보 해석 전제와 사용자가 선택한 입력·편집·표시 기준.
---

직접 쳐서 악보를 만드는 방식의 가능성을 평가할 때, 타격 직후 표기를 확정해야 한다는 전제를 두지 않는다. 사용자는 이후 문맥을 확인하면서 임시 표기를 갱신하는 방식을 논의하고 있다.

**Why:** 사용자가 “당장 악보를 듣자마자 써야” 할 필요는 없다고 정정했다. 초기 타격만으로 판단해야 한다는 제약을 임의로 추가하면 실제로 검토 중인 시스템과 다른 시스템을 평가하게 된다.

**How to apply:** 즉시 관측 가능한 입력과 이후 문맥으로 추정하는 기보를 구분한다. 이 논의는 구현 승인이나 모든 연주 의도를 자동으로 확정할 수 있다는 보장이 아니다.

우선하는 사용 상황은 “떠오른 리듬을 쳐서 빠르게 악보로 기록”이다. 사용자는 “악보를 따라 치며 정확도 연습”도 되면 좋겠다고 밝혔다.

**Why:** 사용자가 사용 상황의 우선순위를 직접 선택했다.

**How to apply:** 입력·수정 흐름은 리듬 기록을 우선해 검토하고, 따라 치기 연습을 추가 목표로 고려한다. 건반 멜로디·화음 입력이 불필요하다고 해석하지 않는다.

리듬 입력은 “BPM·박자를 설정하고 예비박을 들은 뒤 입력”하는 방식으로 검토한다.

**Why:** 사용자가 자유 연주 후 템포·박자를 추정하는 방식 대신 이 방식을 선택했다.

**How to apply:** 설정된 기준 박을 이용한 기보 해석을 전제로 삼는다. 자유 템포 분석을 확정된 요구사항으로 추가하지 않는다.

자동 기보는 “읽기 쉽게 정리하되 보정 정도를 조절 가능”한 방향이다.

**Why:** 사용자가 자동 정리 기준으로 조절 가능한 보정을 선택했다.

**How to apply:** 보정 정도를 조절하되 전체에 같은 보정을 적용한다. 구간별 별도 보정은 사용자가 선택하지 않았다.

## 사용자가 선택한 동작 기준

- 입력 화면은 큰 패드를 기본으로 드럼·건반으로 전환한다.
- 패드·드럼은 타격 중심, 건반은 누른 길이를 반영한다.
- 입력 종료는 마디 수 지정 또는 직접 정지 중 선택한다.
- 자동 재해석은 미확정 구간만 변경하고 직접 확정한 곳은 보호한다. 사용자는 “너무 길게 문맥을 읽으면 안되”라고 명시했고, 문맥 길이 상한으로 최대 한 마디를 선택했다.
- 드래그는 해당 음만 이동하고 주변 음길이·쉼표 변경안을 미리 보여준다.
- 단일 리듬의 쉼표·복잡한 연음부터 완성하는 것을 우선한다.
- 따라 치기에서는 타격 시점과 누락·추가 타격을 평가한다.
- 악보 색상에 대해 사용자는 “오선지는 무조건 휜색,검은샏으로”라고 명시했다.

**Why:** 사용자가 제시된 선택지와 추가 의견으로 직접 정한 요구사항이다.

**How to apply:** 향후 설계와 구현 범위에 이 기준을 반영한다. 최대 한 마디는 해석에 참고하는 문맥의 상한이지, 표시를 한 마디 끝까지 지연시키라는 요구가 아니다. 입력 화면의 세부 배치는 아직 확정된 것으로 취급하지 않는다.

## 도형 도구

사용자는 손으로 거칠게 그리는 입력이 아니라 “타원·선·곡선으로 기호를 구성하고 악보 요소로 지정”하는 도형 도구를 선택했다.

**Why:** 사용자가 “그려서가 아니라 그릴수 있는 도형툴이야. 거칠게 만들기 싫거든”이라고 정정한 뒤 도형 구성 방식을 선택했다.

**How to apply:** 완성 기호 배치만으로 요구를 대체하거나 단순 도형 주석으로 축소하지 않는다. 도형의 외형과 지정된 음악적 의미를 구분한다. 자동 인식이나 임의 기호의 재생 의미까지 확정된 요구로 추가하지 않는다.

사용자가 직접 부호를 만드는 이유는 “너무 많은 부호가 있고 전부 알고리즘으로 넣는건 힘들수” 있기 때문이다. 예로 “나는 플램으로 쳤는데 32연음으로 인식”하는 경우를 들었다. 사용자 부호는 단순 외형 꾸미기가 아니라 자동 해석과 다른 자신의 연주 의도를 지정하는 수단이다.

**Why:** 사용자가 루디먼트 검토 이후 직접 도형 부호를 넣은 목적을 명시적으로 설명했다.

**How to apply:** 모든 루디먼트 이름과 기법을 자동 인식 알고리즘에 내장하는 것을 선행 조건으로 삼지 않는다. 선택한 실제 타격들에 부호의 음악적 역할을 연결해 해석을 바로잡는 흐름으로 설계한다. 원래 입력 보존과 직접 확정한 구간 보호를 유지하며, 임의 외형만으로 재생 의미까지 자동 추론한다고 약속하지 않는다.

## 추가로 확정한 편집·재생 기준

- 입력 종료 후 악보 초안을 확인한 뒤 확정한다.
- 음표 미세 조정은 박·연음 위치에 붙이기를 기본으로 하고 자유 이동으로 전환할 수 있다.
- 수정 후에도 기본 재생은 원래 입력이며, 수정된 악보는 비교 듣기로 제공한다.
- 해석 후보는 애매하거나 수정한 구간에서 제시하고 사용자가 직접 열 수도 있다.
- 도형으로 만든 기호의 음악적 역할과 속성은 사용자가 직접 지정한다.
- 직접 만든 기호는 개인 기호함에 저장해 재사용한다.
- 첫 연음 표현·편집 범위는 일반 연음과 음길이·쉼표가 섞인 연음, 사용자 지정 비율, 중첩 연음, 마디선을 넘는 연음을 모두 포함한다.

**Why:** 사용자가 남은 동작 선택지에서 각 항목을 직접 선택했고 연음 범위는 네 항목 모두 선택했다.

**How to apply:** 원래 입력을 기본 재생으로 선택한 것을 수정된 악보 기본 재생으로 바꾸지 않는다. 연음 표현·편집 지원을 모두 자동 인식한다는 보장으로 확대하지 않는다. 마디선을 넘는 연음 지원 때문에 자동 해석 문맥의 한 마디 상한을 임의로 늘리지 않는다.

## 추가 세부 동작 선택

- 패드·드럼 타격의 기본 해석은 짧은 음으로 적고 남는 시간은 쉼표로 한다. 입력 중 쉼을 명시하는 조작으로는 패드를 누르는 동안 음을 유지하고 떼면 쉼으로 하는 방식을 선택했다.
- 건반은 멜로디와 동시에 누르는 화음까지 지원한다. 독립 성부까지 첫 범위로 선택한 것은 아니다.
- 복잡한 연음은 자동 해석 후보로 제안하고 사용자가 직접 선택한다.
- 보정 조절은 미세한 차이를 단순한 리듬으로 정리하는 정도를 바꾼다. 별도 시점 보정 강도 조절을 선택한 것으로 확대하지 않는다.
- 도형 기호의 지정 가능한 역할은 시간·리듬, 음높이·임시표·조옮김, 강약·아티큘레이션·주법, 템포·반복·이동 지시를 모두 포함한다.
- 도형 기호는 지원하는 역할을 악보 비교 재생에 반영하고, 미지원 역할은 명시한다.
- 따라 치기 허용 오차는 BPM·음 간격에 맞추고 난이도도 선택한다. 사용자는 “오프셋? 영점? 타이밍? 맞추는 기능도 필요하겠네”라고 추가했다.
- 따라 치기는 종합 점수와 항목별 결과를 함께 표시하고, 진행 중 간단한 표시와 종료 후 상세 결과를 제공한다.
- 입력 화면은 큰 패드 중심과 작은 악보 미리보기를 선택했으며, “패드는 터치 용이할 정도만 기본으로 하고 크기 조정”이라고 덧붙였다.
- 악보 줄 수는 “가로나 패드 처럼 한줄에 두마디 이상 보여주는 비율에서는 한줄, 그 이하는 두줄”로 한다.
- 해석 후보는 선택 구간을 보면서 아래 후보 패널에서 비교한다.

**Why:** 사용자가 각 선택 항목에 답하고 타이밍 맞추기 및 화면 구성에 추가 의견을 제시했다.

**How to apply:** 패드의 짧은 타격 기본값과 누름 유지 조작을 함께 반영한다. 영점/오프셋과 판정의 구체적인 기준은 다음 절의 선택에 따른다. 큰 패드 중심이라는 선택을 화면을 고정적으로 크게 차지하는 패드로 해석하지 않는다. 악보 줄 수는 기기 이름만이 아니라 한 줄에 두 마디 이상 표시 가능한 비율을 기준으로 삼는다.

## 영점·기본 음가·연습 판정 기준

- 영점/오프셋은 기준음을 듣고 16회 타격해 맞춘 뒤 수동 미세 조정도 제공한다. 이 방식은 기기 지연만 분리 측정하는 것이 아니라 개인 반응 습관이 포함된 체감 보정이다. 원래 입력 시각은 보존한다.
- 짧은 타격의 기본 음가는 16분음표다. 사용자는 “64분음표도 할수 있어야해”라고 추가했다. 기본 음가를 최소 지원 음가로 취급하지 않는다.
- 사용자는 지원 범위를 “16 24 32 64 등등 다 되는거지?”라고 확인했다. 일반 음가뿐 아니라 24분음표 길이처럼 연음으로 표기하는 분할도 표현·편집 범위에 포함한다.
- 따라 치기 시작 허용 오차는 BPM 기준 한 박 대비 쉬움 ±15%(최대 90ms), 보통 ±10%(최대 60ms), 엄격 ±5%(최대 35ms)다. 가까운 앞뒤 음 간격의 45% 이내로 추가 제한하며 한 타격은 한 음에만 대응한다.
- 종합 점수는 누락·추가 타격 70%, 타이밍 정확도 30%로 한다. 개별 항목 결과도 별도로 표시한다.

**Why:** 사용자가 제시된 네 가지 세부 기준을 선택하고 64분음표 지원을 명시했다.

**How to apply:** 위 판정 수치는 첫 적용 기준으로 사용한다. 16분음표 기본값 때문에 64분음표 입력·표현·편집을 막거나 항상 16분음표로 뭉개지 않도록 한다. 아직 구현 요청은 아니므로 요구사항 합의를 앱 구현 완료로 안내하지 않는다.

## 루디먼트 검토 시의 구분

루디먼트 지원 가능성을 설명할 때 정량 음가, 플램·드래그의 꾸밈 타격, 축약 롤, 실제 재생 타격, 좌우 손순서를 구분한다. 모든 것을 촘촘한 음표나 루디먼트 이름 프리셋으로 대체하는 설계는 피한다.

**Why:** 사용자가 복잡한 드럼 루디먼트 레퍼런스를 모아 구현 가능성을 검증해 달라고 요청했다. 동일한 타격 시각에 다른 손순서·기법·기보 의도가 대응할 수 있어 표현 가능성과 자동 복원 가능성은 다르다.

**How to apply:** PAS와 Vic Firth를 기준 레퍼런스로 활용한다. 한 패드의 타격 시각만으로 손순서·압력·바운스 기법까지 알아낸다고 약속하지 않는다. 연구 결과와 실제 앱 입력·청취·기기 검증을 분리해 안내한다.

영상·악보 조사에 대해 사용자는 “영상·악보를 분석해서 자동 기보 알고리즘을 설계하기”를 선택하고 “시스템 알고리즘 구축을 검증하고 견고히 하는 과정 아닌가?”라고 목적을 확인했다.

**Why:** 기능 목록 도출과 알고리즘 설계를 불필요하게 분리한 설명을 바로잡기 위해 사용자가 조사 목적을 명확히 했다.

**How to apply:** 사례에서 자동 해석 규칙·반례·사용자 부호를 통한 수정 제약을 도출하고 검증한다. 단순 레퍼런스 수집으로 축소하지 않으며, 이 선택을 실제 앱 구현 시작이나 모델 훈련 승인으로 확대하지 않는다.

## 실험실 내 신규 기능의 범위

사용자는 “실험실에 있는 악보모드에서 필요한 부분만 빼고 실험실에 새로 만드는거지?”라고 작업 구성을 확인했다. 기존 악보 모드의 필요한 부분을 재사용해 현재 앱의 실험실 안에 새 기능을 구성하는 방향이다.

**Why:** 사용자가 새 기능의 위치와 기존 악보 모드 재사용 범위를 명시적으로 확인했다.

**How to apply:** 필요한 부분을 가져온다는 말을 기존 기능 삭제로 해석하지 않는다. 기존 악보 모드와 저장 악보는 유지한다. 별도 앱 생성이나 기존 악보 모드 전체 교체를 전제로 진행하지 않는다. 새 기능에 필요한 시간·연음·꾸밈 타격 구조는 기존 제약에 억지로 맞추지 않고 설계한다.

## 오선지와 펜 자체인 자유 드로잉

사용자는 “그냥 오선지를 제공하고 악보를 그릴수 있게도 가능하게 해줘”, “여기서 그린다는건 실제 드로잉이야”라고 요청했다. 이어 “이건 앞선 것들과 다르게 진짜 오선지와 펜 그 자체야. 거기에 간단한 메트로놈 정도를 곁들인?”이라고 범위를 정정했다.

**Why:** 자유 드로잉을 앞선 자동 기보 시스템에 속한 또 다른 입력 방식으로 설명한 오해를 사용자가 바로잡았다.

**How to apply:** 종이 오선지와 펜을 옮긴 오선 노트로 다룬다. 그린 선은 선 그대로이며 자동 인식·박자 보정·음악적 의미 지정·악보 재생을 전제하거나 사용 조건으로 붙이지 않는다. 간단한 메트로놈을 곁들인다. 도형 부호 도구나 자동 기보 기능으로 대체하거나 앞선 시스템의 필수 입력 단계로 묶지 않는다. 흰 오선지·검은 표기 기준을 유지한다.
