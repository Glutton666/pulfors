---
name: 오선노트 작업영역 방향
description: 종이 중심 작업영역, 오른쪽 모드 메뉴·하단 도구, 혼합 객체 선택·복사와 재생 설정에 관한 사용자 요구.
---

오선노트는 위의 다이얼 영역을 유지하고 나머지 영역을 오선노트로 채운다. 오른쪽 화살표를 펼치면 필기모드·음표모드·선택모드·설정을 고르는 메뉴가 나온다. 선택한 모드의 도구줄은 처음에 하단 중앙에 두되 전용 핸들로 옮길 수 있게 한다. 왼쪽에 있던 기능은 오른쪽 설정으로 옮기되 기본 재생 조작은 아래에 설명한 재생바로 분리한다.

**Why:** 사용자가 종이 중심 작업영역은 유지하면서 기존 좌우 기능 분리 구상을 모드 선택과 하단 고정 도구 방식으로 변경했다. 왼쪽 기능 전부 이동을 선택한 뒤 재생은 설정 밖 오선노트 상단으로 분리하도록 추가 지정했다.

**How to apply:** 오선노트 레이아웃을 변경할 때 새 모드 구성을 기준으로 한다. 상단 다이얼은 유지하고 모드와 무관한 도구로 종이를 가리지 않는다.

기본 재생 조작은 접고 펼칠 수 있는 간단한 재생바로 둔다. 재생바와 하단 도구줄 모두 화면 전체 너비를 차지하지 않고 필요한 너비로 중앙에 띄우며, 양옆은 종이 작업영역으로 사용한다. 재생바의 초기 위치는 상단 중앙이고 두 바 모두 전용 핸들로 끌어 옮긴다. 한 줄에 박자 선택·BPM·무작위 재생 전환·재생을 두며, 무작위 전환은 재생 버튼 바로 왼쪽에 둔다. 박자 선택에서 1/4·2/4·3/4·4/4 등의 목록을 연다.

**Why:** 사용자는 재생 조작을 설정 밖 오선노트 상단으로 분리한 뒤, 두 바를 작게 중앙에 배치하자는 해석을 확인하고 “핸들을 달아서 핸들로 끌어서 움직일수 있게” 하겠다고 추가했다. 이후 재생 왼쪽 무작위 전환, 필기 도구줄 오른쪽 여백 제거, 음표 편집 도구줄 한 줄 배치를 요청했다. 세로에서 필기 기능이 한눈에 안 들어오는 점을 지적하며, 펜을 길게 눌러 세 도구를 고르고 오른쪽에 생략됐던 기능을 꺼내도록 변경했다.

**How to apply:** 상단 다이얼은 유지한다. 바의 위치를 종이 스크롤과 분리하고, 버튼 자체를 누르거나 음표를 고르는 동작을 바 이동으로 취급하지 않는다. 접기·펼치기와 핸들 이동은 재생 명령이 아니다. 필기에서는 현재 도구 버튼을 길게 눌러 펜·지우개·화면 이동을 선택하고, 오른쪽의 실행 취소·다시 실행·확대/축소는 세로 화면에서도 숨기거나 가로로 밀어 찾게 하지 않는다. 음표 편집은 한 줄 구성을 유지하되 좁은 화면에서도 모든 기능에 접근할 수 있게 한다.

도구줄의 좌표 재측정과 팝업 닫기는 작성 중인 잇단음표 같은 문서 입력 상태를 초기화하면 안 된다.

**Why:** 잇단음표 작성 상태줄 때문에 도구줄 높이가 바뀌었을 때, 재배치 알림이 문서 입력 취소까지 호출하면 열어 둔 묶음이 사라졌다.

**How to apply:** 이동·회전·도구줄 크기 변경은 메뉴 좌표와 미완료 선택 제스처만 갱신한다. 잇단음표를 연 상태에서 음표·쉼표 추가 후 닫는 흐름을 함께 검증한다.

설정에서 연습장의 패턴을 불러올 수 있게 하며, 별도로 간단한 1/4 메트로놈의 템포를 설정해 재생할 수도 있다.

**Why:** 사용자가 단순 메트로놈 대안을 제시한 뒤 연습장 패턴 불러오기도 명시적으로 요청했다.

**How to apply:** 패턴 재생과 단순 메트로놈 양쪽을 제공하되, 단순 메트로놈 사용에 불러오기를 필수로 요구하지 않는다.

불러온 패턴은 BPM만 가져오는 것이 아니라 강약·쉼표·서브디비전·반복 등 원래의 재생 의미를 유지한다. 지원하지 않는 항목은 분명하게 안내하고 단순 클릭으로 대체하지 않는다.

**Why:** 패턴 불러오기와 간단한 1/4 메트로놈은 서로 다른 재생 소스다. 둘을 같은 클릭으로 처리하면 사용자가 지정한 줄의 시간 기준과 실제 소리가 달라진다.

**How to apply:** 새로운 연습장 항목을 오선노트에서 지원할 때 소리와 줄 대응을 함께 확인한다. 기존 패턴을 재현하지 못하는 항목을 지원하는 것처럼 노출하지 않는다.

오선노트의 줄 기준 선택에서 사용자가 말하는 ‘한 박자’는 한 박이 아니라 4마디 묶음이다. 사용자는 4/4·BPM 60에서 한 줄을 한 마디로 보면 4초, 한 박자로 보면 16초라고 정정했다.

**Why:** ‘한 박자’를 한 박 길이로 확인하려 했을 때 사용자가 “한 박이 아니라 한 박자이고 한 박자는 위 기준 16초야”라고 바로잡았다.

**How to apply:** 이 기능의 사용자 정의 구간 명칭으로 취급하고, 한 박으로 바꾸거나 항상 16초인 고정 길이로 처리하지 않는다. 재생 소스의 박자·템포에 따라 한 마디 또는 4마디에 대응시킨다.

악보 따라가기는 설정에서 켜고 끄며 재생 확대 배율을 설정한다. 재생 진행과 동기화해 하이라이트 없이 현재 줄을 화면 중앙으로 따라가되, 자동 이동은 세로 방향만 하고 좌우로 추적하지 않는다. 랜덤 재생은 원본의 줄 사이를 뛰는 대신 미리 마디·박자 구간을 섞은 악보를 제공한다.

**Why:** 사용자가 따라가기의 기준과 재생 시 화면 동작, 랜덤 악보 구성을 직접 지정한 뒤 “재생에서 트래킹하는거 아에 세로이동만 하자”라고 방향을 제한했다.

**How to apply:** 필기를 자동 인식하는 것이 아니라 지정한 줄 단위와 재생 진행을 대응시킨다. 재생 진행률에 따라 가로 스크롤을 바꾸지 않는다. 랜덤 재생용 악보와 음원의 순서를 일치시키고 원본 필기 순서는 보존한다.

트래킹 설정에 반복·이동 기호 따라가기를 켜고 끄는 옵션을 제공한다. 켜면 오선노트에 배치한 반복·이동 부호에 따라 진행하고, 끄면 종전처럼 지정한 줄 단위로 순서대로 진행한다.

**Why:** 현재는 종이의 부호를 해석하지 않는다는 설명을 들은 사용자가 기능을 만들고 설정에서 켜고 끌 수 있게 하자고 요청했다.

**How to apply:** 기호를 단순히 함께 스크롤하는 것과 기호의 뜻에 따라 진행 경로를 바꾸는 것을 구분한다. 옵션을 켜도 자동 화면 이동은 세로 방향만 유지하고, 소리와 화면이 같은 진행 순서를 사용하게 한다. 필기 인식이나 개별 음표 음원 합성 요구로 확대하지 않는다.

음표모드에서 음표에 붙는 기호는 제일 마지막에 놓은 음표에 처음 붙이고, 사용자가 기호를 드래그하면 위치를 옮길 수 있게 한다. 독립 기호·부호는 현재 작성 중인 줄이나 부분 근처에 나타나고, 아무것도 작성하지 않았으면 첫 줄 첫 부분에 나타나게 한다. 음표 위치 보정은 세로 방향이며 설정에서 켜고 끄기만 한다.

**Why:** 사용자가 기호의 출현 위치와 세로 보정 켜기·끄기를 지정한 뒤, 음표 부착 기호는 마지막 음표에 붙이되 드래그로 이동하고 독립 기호는 작성하던 줄 근처에 소환하도록 구분했다.

**How to apply:** 자동 부착을 위해 사용자가 대상 음표를 다시 누르도록 강제하지 않는다. 자동 부착은 수동 위치 조정을 막거나 덮어쓰지 않으며, 독립 기호에는 현재 작성 위치와 빈 노트의 시작 위치를 구분한다. 가로 좌표는 보정하지 않으며 음악적 해석이나 재생 시간 보정으로 바꾸지 않는다.

설정에서 한 페이지에 몇 줄의 오선을 둘지 사용자가 정할 수 있게 한다.

**Why:** 사용자가 “설정에 한 페이지에 몇 줄할건지도 정하자”라고 요청했다.

**How to apply:** 화면에 임시로 보이는 줄 수와 페이지에 지정한 줄 수를 구분한다. 화면 회전·크기 변화로 사용자 설정을 임의 변경하거나 줄 수 변경으로 기존 내용을 잃지 않도록 한다.

선택모드는 필기 객체와 음표 객체를 개별 또는 드래그로 선택하고 하이라이트한다. 선택한 객체를 드래그해 놓으면 해당 위치에서 이동할지 같은 내용을 복사할지 고른다. 선택 중 클립보드에 저장 버튼을 보여 현재 선택한 것을 보관한다.

**Why:** 사용자가 선택 → 드래그 → 멈춘 위치에서 이동/복사 선택 순서를 직접 설명하고, 확인 질문에 현재 선택을 클립보드에 저장하는 버튼을 요청했다.

**How to apply:** 선택 자체나 드래그 미리보기로 원본을 확정 이동하지 않는다. 이동·복사 확정과 클립보드 저장을 구분하고, 선택되지 않은 객체를 보관하지 않는다. 사용자가 한눈에 안 들어오는 선택도구의 재구성을 승인했다. 기본 화면은 개별·영역 / 마디 / 줄과 선택 개수를 보여주고, 선택한 뒤에만 별도 작업줄에 내부 편집·클립보드 저장·삭제·해제를 표시한다. 크기 조절은 보조 메뉴로 분리하며 주요 작업을 가로로 밀어 찾게 하지 않는다.

오선노트의 기본 노말 음표는 일반 악보 표기다. 온음표에는 기둥이 없고, 단순히 납작한 타원 테두리보다 안쪽 구멍이 기울고 두께 차이가 있는 통상적인 온음표 머리를 사용한다. 일반 음표에 고스트 괄호를 붙이지 않으며, 짧은 음표의 꼬리는 통상적인 깃발 형태로 표시한다. 고스트를 명시적으로 고른 음표와 기본 노말을 구분한다.

**Why:** 비트·바의 normal 역할은 괄호가 붙은 고스트 모양이어서, 이를 일반 악보 음표로 재사용하면 의미가 달라진다. 사용자가 온음표의 기둥·고스트 괄호·비표준 꼬리를 각각 지적했고, 온음표 머리도 “너무 그냥 납작 동그라미” 같다고 수정 요청했다.

**How to apply:** 메트로놈의 강약 역할과 악보 음가의 표시를 구분한다. 팔레트와 배치된 음표에 같은 벡터 기호를 사용하고 비트·바의 기존 역할 표시는 변경하지 않는다.

음표 도구에 처음 터치하면 좌우의 다른 항목이 사라지고 좌우 드래그로 고스트·노말·스트롱을 고른다. 위로 드래그하는 것은 종이 배치가 아니라 세로 목록에서 음가를 고르는 동작이며, 원하는 음표 위에서 왼쪽은 해당 음가의 점음표, 오른쪽은 점 없는 해당 음표를 고른다.

**Why:** 사용자가 그림을 설명하며 세로 드래그는 목록 선택이라고 확인하고, 최초 터치와 음가 선택 이후의 좌우 동작을 구분했다. 이후 쉼표 같은 옆 도구와의 겹침을 지적하고 선택 단계별로 기존 도구줄을 숨기는 구성을 승인했다.

**How to apply:** 음표 종류 선택 단계와 점 유무 선택 단계가 서로 덮어쓰지 않게 한다. 이미 고른 종류는 음가·점 유무 선택에서도 유지하고, 목록을 드래그하는 도중에는 종이에 음표를 찍지 않는다. 음표·쉼표 제스처 중에는 원래 도구줄과 열린 부가 메뉴를 숨기고, 강도 단계에서는 강도만, 음가 단계에서는 음가와 점 유무만 표시한다. 손을 떼거나 취소하면 원래 도구줄을 복원한다.

음표를 고르는 제스처가 끝나면 선택한 음표는 작성하던 줄 근처에 나타난다. 처음 작성하는 경우 첫 줄 첫 부분에 놓인다.

**Why:** 사용자가 배치 동작을 “고르는 제스처가 끝나면 작성하던 줄 근처에 나타나거나 처음 이면 처음 줄 처음에 놓는 느낌”이라고 설명했다.

**How to apply:** 위로 움직이는 동안은 음가 선택이며, 선택 제스처가 끝나는 시점에 작성 위치를 기준으로 음표를 놓는다. 악보까지 끌어가는 동작이나 별도의 ‘여기에 놓기’ 확인 단계를 추가하지 않는다.

음표 이동은 손가락의 절대 위치를 따라붙는 방식이 아니라, 음표의 이동 시작 위치에서 손이 움직인 방향과 거리만큼 상대 이동하는 방식이다.

**Why:** 사용자가 “음표를 옮길때 내 손을 따라가는게 아니라 손이 움직이는대로 움직이기만 하면 좋겠어”라고 지정했다.

**How to apply:** 이동 시작 시 음표 위치와 터치 위치를 각각 보관하고, 음표의 원래 위치에 터치 시작점 대비 이동량을 더한다. 터치 시작점으로 음표를 순간 이동시키지 않으며, 확대된 화면에서는 이동량을 악보 좌표로 변환한다.

잇단음표는 괄호를 열고 그 안에 음표·쉼표를 넣은 다음 괄호를 닫으면, 들어간 음표·쉼표 개수에 따라 위에 숫자가 표시되는 방식이다.

**Why:** 사용자가 ‘연음’은 붙임줄이 아닌 잇단음표라고 확인한 뒤, 괄호 열기·내용 넣기·괄호 닫기의 작성 순서와 자동 개수 표시를 직접 설명했다.

**How to apply:** 처음부터 3연음·5연음 숫자를 고르는 방식으로 대체하지 않는다. 포함된 음표·쉼표를 기준으로 묶음을 만들며 재생 시간 비율이나 붙임줄로 임의 해석하지 않는다.

잇단음표의 표시 모양은 표준 악보 레퍼런스와 대조한다.

**Why:** 사용자는 위치를 따라가는 문제를 묻는 것으로 해석한 답변을 바로잡고 “잇단음표 레퍼런스랑 비교해봐”라고 요청했다.

**How to apply:** 표시 모양에 관한 요청을 이동·트래킹 문제로 단정하지 않는다. 괄호·숫자의 형태와 간격을 확인하되, 사용자가 정한 괄호 열기·닫기와 개수 기준을 바꾸지 않는다.

빔 연결은 사용자가 지정한 잇단음표 묶음에만 적용하며, 처음에 놓거나 중간에 넣은 쉼표 때문에 연결 범위를 끊지 않는다.

**Why:** 사용자가 “잇단음표만 적용하고 … 쉼표 음표사이에 들어가면 빔연결 끊기는데 이러면 안되”라고 범위를 바로잡았으며, “내가 잇단음표 표시를 켜고 만든 객체에만 적용되야” 한다고 재차 명시했다. 이 화면에서 사용자가 말하는 잇단음표에는 명시한 묶음의 빔 연결이 포함된다.

**How to apply:** 일반 음표는 박자나 인접 여부만으로 자동 연결하지 않는다. 기존 잇단음표 열기·닫기로 정한 묶음 안에서 음가에 맞게 연결한다. 첫 객체가 쉼표여도 묶음의 시작 범위를 유지하고, 중간 쉼표를 넘어 앞뒤 음표의 빔을 유지한다. 쉼표에 음표 기둥을 붙이거나 실제 음가·재생 시간을 바꾸지 않는다.

기둥·꼬리의 표준 모양과 음표 사이의 빔 연결은 별도로 검토한다.

**Why:** 사용자는 자동 빔을 적용한 뒤에도 사진을 주며 기둥과 꼬리가 레퍼런스와 다르다고 지적했다. 연결 규칙이 맞아도 개별 음표의 윤곽이 잘못될 수 있다.

**How to apply:** 빔 연결 테스트만으로 표준 표기가 완성됐다고 안내하지 않는다. 독립된 8·16·32분음표의 꼬리 사이 빈 공간, 기둥 길이·접합부를 실제 렌더링에서 비교하고, 긴 음표를 억지로 빔으로 연결하지 않는다.

빔 연결에 쓰는 기보 박자와 음가 계산은 메트로놈·패턴 재생 시계와 분리한다.

**Why:** 지정 묶음 안의 표기를 바꾸기 위해 기존 메트로놈 재생이나 줄 따라가기의 시간을 변경하면 별도 기능까지 영향을 받는다.

**How to apply:** 기보용 잇단음표 길이 환산은 빔 경계 계산에만 사용한다. 기보 박자를 변경해도 저장된 음가·위치와 재생 BPM·박자·패턴을 변경하지 않는다.

쉼표도 음표와 같은 방식으로 고르고 놓는다.

**Why:** 사용자가 “쉼표도 음표랑 똑같은 방식으로 사용할수 있게 해줘”라고 요청했다.

**How to apply:** 쉼표만 별도 격자 메뉴로 되돌리지 않는다. 위로 음가를 고르고 좌우로 점 유무를 고른 뒤 제스처 종료 시 작성 위치에 놓는다.

오선노트 자동 배치의 목표는 음악적 간격과 시각적 가독성을 함께 유지하는 것이다. 잇단음표는 배치 단위로 묶되 내부 간격을 확보하고, 비율은 표준값 자동 적용 및 사용자 수정을 지원한다.

**Why:** 사용자는 초기의 “모든 객체를 같은 간격으로” 요구를 이후 음악적 자동 배치·묶음 가독성·자동 축척 요구로 구체화했다.

**How to apply:** 자동 조정 끄기는 현재 배치를 되돌리지 않으며 복원은 이전/이후로 한다. 자동 조정 중 음표 이동은 놓은 순서로 재정렬한다. 음악적 시간 초과와 시각적 과밀은 구분하며, 축소로 음악적 초과를 숨기거나 사용자 승인 없이 마디 수를 늘리지 않는다.

기보와 불러온 패턴은 서로 영향을 주지 않고 템포 정도만 일치시킨다. 줄당 마디 수는 직접 설정하고 기보상 마디 자동 나누기는 켜고 끌 수 있게 한다.

**Why:** 사용자는 “패턴과 기보는 서로 영향x, 템포정도 일치하도록”, “마디수 직접 설정+기보 상 마디수 자동 나누기 on,off”라고 지정했다.

**How to apply:** 패턴 박자로 기보 박자를 덮어쓰지 않는다. 자동 마디 나누기를 단순 표시 토글이라고 단정하지 말고 의미를 확인한다. 펜 필기는 자동 배치에서 제자리를 유지하되 사용자가 선택으로 묶어서 이동할 수 있게 한다. 넘침을 넘기는 배치는 이후 줄까지 고려한다.

줄·마디 단위 선택을 지원하며, 해당 범위를 이동할 때 필기가 포함되어 있으면 “필기가 포함되어 있습니다. 같이 옮길까요?” 메시지로 사용자가 포함 여부를 선택하게 한다.

**Why:** 사용자는 줄·마디 단위 선택을 요청하고 필기는 고정 포함이나 설정 토글 대신 메시지를 띄워 선택하라고 지정했다.

**How to apply:** 수동 이동의 필기 포함 확인과 자동 배치에서 필기를 제자리에 두는 규칙을 구분한다. 필기가 없는 이동에는 불필요한 확인을 추가하지 않는다.

자동 마디 나누기 OFF는 마디선만 숨긴다. 음악적 줄 초과는 다음 줄로 보내고, 마디를 넘는 단일 음표는 분할·붙임줄로 표현한다. 잇단음표는 마디 경계를 넘지 못한다.

**Why:** 사용자가 상황별 선택지에 직접 지정한 기보 규칙이다.

**How to apply:** 미완성 마디와 동시음 해석은 사용자가 상황에 따라 다르다고 했으므로 일괄 규칙을 가정하지 않는다. 한 마디보다 긴 묶음의 처리도 별도 확인한다.

마디는 음악적 단위이고 줄은 표시 단위다. 줄당 마디 수는 기본 배치 개수이며 사용자가 넘기기를 선택한 줄의 실제 개수는 다를 수 있다. 수동 마디선은 기존 경계의 표시 위치를 지정할 뿐 마디 수·음가·기존 음표 소속을 바꾸지 않는다. 음표 자체를 다른 마디로 옮기는 것은 별도 음악 편집이다.

**Why:** 사용자가 “설정 마디 수 유지”를 선택한 뒤, 경계 위치 편집과 음악적 내용 편집을 분리하는 정리를 승인하고 수정을 요청했다. 마디선을 움직였다는 이유만으로 4박이 5박이 되거나 음표의 소속이 바뀌면 안 된다.

**How to apply:** 선택·재생·랜덤은 같은 마디 소속을 사용한다. 수동선 추가·이동·삭제 시 자동 조정 ON일 때만 앞뒤 시각 배치를 조정한다. OFF는 기존 위치·소속·음가를 유지하고 초과·부족을 임의 해결하지 않는다. 내부 경계보다 많은 수동선은 마디 수 변경을 안내한다.

잇단음표 일부 선택은 전체 묶음 선택으로 확장한다. 구성원 삭제 시 남은 개수로 비율을 재계산하고 하나만 남으면 해제한다. 작성 중에도 배치하며 새 음표는 마지막 작성 객체 뒤에 넣고 붙여넣기는 뒤 객체를 민다.

**Why:** 사용자가 묶음 편집 및 삽입 규칙을 선택했다.

**How to apply:** “비율 전체 적용”의 범위를 임의 해석하지 않는다. 이미 닫기를 누른 묶음에 추가하는 규칙과 부착 기호의 상대 위치 규칙은 추가 확인한다.

여러 줄·마디는 시작부터 끝까지 드래그로 선택하며 경계에 걸친 객체·기호·필기 획은 전체 포함한다. 복사·클립보드에서도 필기가 있으면 포함 여부를 묻는다. 줄 이동은 빈 공간을 포함한 줄 순서를 이동한다. 마디 이동의 빈자리와 줄당 마디 수 변경은 자동 조정 ON일 때 당김·재배치, OFF일 때 기존 배치를 유지한다.

**Why:** 사용자가 선택 범위와 자동 조정 여부에 따른 편집 동작을 지정했다.

**How to apply:** 수동 마디선이나 의도적 빈 마디를 당겨 없애는 것으로 확대 해석하지 않는다. 페이지당 줄 수 변경은 줄 순서를 보존한 재분할을 선택했지만 필기·축척과의 세부 관계는 확인한다.

자동 축척은 페이지 전체에 동일하게 적용하고 오선·음악 객체를 함께 축소한다. 사용자는 최소 배율을 “65퍼 정도”로 제안했고, 부족하면 줄당 마디 수 변경 제안·추가 축소·넘기기를 원한다.

**Why:** 사용자가 축척 단위와 과밀 처리 선택지를 지정했다.

**How to apply:** 사용자는 자동 범위를 65~100%로 확정했다. 축척 변경에서는 필기도 함께 변환한다. 페이지당 줄 수 변경 시에도 필기는 해당 줄과 함께 이동한다. 음악 객체 간격 조정에서 필기를 고정하는 규칙과 구분한다.

과밀 처리에서 물리적인 줄을 삽입하는 경우에는 뒤의 기존 줄 전체를 이동한다. 일반적인 음악 객체 간격 조정에서 필기를 고정하는 규칙을 이 경우에 적용하지 않는다.

**Why:** 새 줄 뒤로 기존 음표만 밀고 필기는 옛 줄에 두면 같은 줄에 작성한 내용이 분리된다. 페이지 경계를 넘을 때도 같은 문제다.

**How to apply:** 음표뿐 아니라 필기·완료 상태·의도적 빈 줄·작성 위치에 같은 줄 대응을 적용한다. 줄을 가로지르는 필기는 필요한 경우 원래 줄의 조각으로 보존하고, 단순 음악적 재배치와 구조적인 줄 삽입을 별도로 검증한다.

따라가기는 패턴 기준을 따르지 않는 것으로 변경했다. 랜덤 단위는 사용자 선택이며 필기를 내용과 함께 표시하고 섞인 순서에서 반복·이동 부호도 해석한다. 다시 섞기 버튼으로만 재추첨하고 원래 순서 복귀 시 현재 순서를 별도 오선노트로 저장할지 묻는다. 재생 중 편집은 정지 후 수행한다.

**Why:** 사용자가 재생·랜덤에 대해 지정한 규칙이다.

**How to apply:** 패턴 기준의 줄 이동을 재도입하지 않는다. 따라가기는 기보 박자·템포 기준이며 랜덤 묶음은 아래 최종 ON/OFF 규칙을 적용한다. 저장할 랜덤 순서는 별도 노트이고 원본을 자동 덮어쓰지 않는다.

줄 작성을 마치고 넘어가면 남은 길이에 쉼표를 자동 표시한다. 음표를 겹쳐 놓으면 동시음 여부를 확인하고, 작성을 마친 잇단음표에 중간 삽입할 때 포함 여부를 확인한다. 부착 기호를 직접 이동하면 연결을 해제하고 해제 이펙트로 알려준다.

**Why:** 사용자가 재질문에 지정한 입력·표시 동작이다.

**How to apply:** 다른 줄에 작성을 시작하면 앞 줄 완료로 판단하며, 자동 조정할 때만 부족분 쉼표를 자동 갱신한다. 주변 위치로 기호를 다시 자동 부착하지 않는다.

비율 변경은 악보 전체 재배치를 원한다. 입력과 뒤따른 배치는 이전 한 번으로 함께 복원한다. 자동 조정 OFF의 마디 초과 음표 분할은 자동 조정할 때 적용하고, 줄당 마디 수 변경은 계산 즉시·위치 유지로 처리한다. 의도적 경계·빈 줄은 보존한다.

**Why:** 사용자가 이력·배치 설정의 상호작용을 지정했다.

**How to apply:** 비율 수정의 전체 적용과 자동 OFF의 위치 유지가 충돌하는 시점은 확인한다. 사용자는 “꾸겨넣기”를 간격·크기 압축으로만 확정했으며, 공간 확보를 위해 시간 비율을 자동 변경하지 않는다. 묶음 내부 편집은 묶음 선택 후 진입한다.

따라가기는 기보 박자·템포 기준으로 유지한다. 반복기호 섞기 ON은 기호 자체도 랜덤 위치에 놓는다. OFF는 기호와 사이 음표를 묶음으로 함께 이동하며 위치 고정이 아니다. OFF일 때만 내부 섞기를 별도로 설정한다. 도돌이표와 이동 부호 모두에 적용한다.

**Why:** 사용자가 기보 기준 따라가기를 선택하고 랜덤 구간 보존 및 추가 설정을 요청했다.

**How to apply:** 구간 전체 이동과 내부 재정렬, 기호 자체 랜덤 배치를 구분한다. OFF 관련 구간은 출발·도착 사이 전체이고 겹쳐 악보 전체가 묶이면 내부 섞기를 허용한 경우 안전한 내부 구간만 섞는다. ON에서도 기호 관계가 유효한 결과를 만들되 항상 원래 구간을 유지하는 OFF 동작으로 대체하지 않는다.

저장·재열기 회귀 검증에서는 문서 내용과 일시적인 편집 상태를 구분한다. 선택 테두리는 저장 대상이 아니므로 재열기 전후의 문서 비교에서 제외한다.

**Why:** 올바르게 선택을 해제하며 노트를 불러왔는데도 전체 SVG 문자열 비교가 필기 손실로 오판했다. 화면을 채우는 자동 줄 확장 역시 저장본의 줄 수와 혼동하기 쉽다.

**How to apply:** 취소·저장 실패 후에는 같은 초안이 남는지 확인하고, 저장·재열기 후에는 필기·기호·줄 수·설정을 비교한다. 줄 수 검증용 기준 문서는 화면 자동 확장보다 충분히 길게 준비한다.

웹 오선노트의 입력 표면은 브라우저 기본 텍스트 선택을 허용하지 않는다.

**Why:** SVG 숫자를 포함하는 범위 선택 뒤 객체를 끌면 브라우저의 네이티브 HTML `dragstart`가 먼저 발생해 정상적인 PanResponder를 취소했다. 빈 영역에서 시작하는 범위 선택만 검증하면 드러나지 않는다.

**How to apply:** 오선노트의 객체 선택·클립보드가 선택을 담당하게 하고, 웹 입력 표면의 `user-select: none`을 유지한다. 회귀 검증은 숫자 있는 잇단음표를 범위 선택한 다음 실제 객체를 끌어 놓는 흐름까지 확인한다.

도구를 처음 터치하기 전에도 펼침 메뉴의 화면 좌표가 유효해야 한다.

**Why:** 웹에서는 모드 전환의 레이아웃 알림이 새 뷰 참조 연결보다 먼저 올 수 있다. 음표나 쉼표를 먼저 드래그한 검증은 좌표를 갱신해, 기호 메뉴를 바로 열면 내용이 잘리는 문제를 숨겼다.

**How to apply:** 모드 진입 직후 다른 도구를 건드리지 않고 기호 메뉴를 여는 흐름을 검증한다. 최초 레이아웃 알림만 신뢰하지 말고 화면 반영 후 좌표를 확보하며, 스크롤 메뉴에는 실제 높이를 할당한다.

오선노트 지우개의 on/off는 활성화 여부가 아니라 객체 전체 지우기와 닿은 부분만 지우기의 전환이다. 이전/이후는 페이지 이동이 아니라 실행 취소/다시 실행이다. 부분 지우기는 음표·기호의 시각적 삭제이며 음악적 음가 변경으로 해석하지 않는다.

**Why:** 사용자가 해당 조작의 뜻과 벡터 객체의 남은 부분 보존을 명시적으로 지정했다.

**How to apply:** 이 조작을 설명하거나 개선할 때 기존 페이지 탐색·재생·자동 빔 규칙과 혼동하지 않는다. 부분 삭제를 객체 전체 삭제로 대체하지 않으며, 두 번째 손가락을 올린 편집 제스처는 취소한 뒤 모든 손가락을 뗄 때까지 화면 이동으로만 처리한다.

공유 빔·잇단음표 괄호는 객체 전체 지우기에서 모든 구성 음표를 삭제하는 대상으로 취급하지 않는다. 직접 닿은 음표 자체나 기둥만 해당 음표 삭제를 허용하고, 부분 지우기에서는 공유 표기의 시각적 일부를 지울 수 있다.

**Why:** 공유 표기의 영역을 모든 구성 음표의 삭제 영역으로 해석하면 음표 사이를 지웠는데 멀리 떨어진 음표까지 사라질 수 있다.

**How to apply:** 시각적 부분 삭제 영역과 음악 객체 전체 삭제 대상을 구분한다. 공유 표기 사이의 빈 위치를 건드려도 구성 음표가 보존되는지 검증한다. 잇단음표 일부를 선택하면 전체 묶음을 선택하는 규칙을 지우개의 직접 접촉 삭제에 확대 적용하지 않는다.
