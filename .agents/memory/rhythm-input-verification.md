---
name: 리듬 입력과 클릭 검증
description: 리듬 입력의 실제 down/up 저장과 화음·메트로놈의 독립 출력 검증 원칙.
---

리듬 입력 검증은 패드의 표시·클릭 성공만으로 끝내지 않는다. 저장된 타격 개수, 실제 누름·뗌 시각, 여러 건반의 독립 release를 확인한다.

**Why:** 브라우저에서 녹음 버튼과 패드가 정상 표시되고 클릭 검사도 성공했지만 실제 타격 콜백이 실행되지 않는 경우가 있었다. 직접 responder 입력으로 바꾼 뒤 원본 타격과 길이를 저장하는 검사가 통과했다.

**How to apply:** 입력 컴포넌트를 바꾸면 실제 브라우저에서 원본 저장 내용까지 검사한다. 단음 미리듣기의 성공을 화음 입력 성공으로 간주하지 않는다.

리듬을 두드리는 패드·건반은 입력 및 연습 중 스크롤에 밀리지 않는 고정 영역으로 유지한다. 리듬 메뉴 탭을 비활성화하라는 뜻이 아니다. 설정과 저장 기록은 각각 설정·연습장 팝업으로 열고, 기본 기록 화면에는 필수 기능이 함께 보여야 한다.

**Why:** 사용자가 “리듬탭은 스크롤이 되면 탭하는 부위가 밀릴거 아니야”라고 터치 차단이 아니라 입력 위치의 안정성을 뜻한다고 정정했다.

**How to apply:** 입력 표면을 스크롤 내용 밖에 유지한다. 예비박과 녹음·연습 시작/종료 때도 표면을 밀거나 불필요하게 재생성하지 않는다. 짧은 가로 화면에서도 설정 스크롤과 시작·정지 조작을 함께 확보하고, 실제 드래그·누름·뗌 저장을 검증한다.

첫 단계의 우선순위는 사용자가 지정한 “탭하는 부위, 기록 버튼과 현재 기록 중인지 상태 표시, 실시간 탭과 탭 사이 간격(ms), 실시간 기보 기록”이다. 큰 제목·설명이나 세로로 늘어진 메뉴 때문에 이 기능을 생략하지 않는다.

**Why:** 사용자가 화면 구성과 설명이 다른 기능을 밀어낼 정도로 필요한지 지적하고, 처음 단계에 필요한 항목을 직접 나열했다.

**How to apply:** 기본 화면에 입력과 상태·실측 간격·악보를 함께 유지한다. 긴 기록은 악보 안에서 탐색하며, 상세 설정·저장 기록·검토 도구는 기존 기능을 없애지 않고 별도 진입점으로 제공한다. 화면 경계뿐 아니라 부모 스크롤/고정 입력부에 실제로 가려지는지도 확인한다.

사용자가 재확인한 패드·드럼 기보 기준은 “짧은 음 + 남는 시간은 쉼표”이다. 탭 간격 전체를 지속음으로 채우거나 마지막 음에 앞 간격·한 박을 복제하는 것을 확정된 요구로 취급하지 않는다. 건반은 실제 누른 길이를 별도로 반영한다.

**Why:** 사용자가 탭 개수만큼 음표를 그리는 문제를 지적한 뒤, 간격 전체를 음가로 채우는 규칙 또한 기존에 확정한 짧은 음·쉼표 기준과 다르다고 재차 명시했다. 기보 규칙의 불일치를 입력 모드 안내만 고쳐 해결한 것으로 간주하지 않도록 한다.

**How to apply:** 다른 간격의 타격열에서 짧은 음과 잔여 쉼표의 위치·길이를 정답 기보와 비교하고 마지막 타격도 별도로 확인한다. 원본 간격과 악보에서 복원한 간격·오차를 비교하되, 타이밍 일치를 올바른 음가나 연주 의도의 확정과 동일시하지 않는다.

자동 기보 검증은 정박·정확한 연음 예제만으로 끝내지 않는다. 늦은 첫 탭과 불규칙한 간격을 포함한 입력의 모든 중간 상태에서도 표시 가능한 음가·쉼표인지 검사한다.

**Why:** 정밀한 격자가 실제 간격과 수 ms만 차이나도 그 격자가 만든 점음표·쉼표를 표시하지 못할 수 있다. 단위·브라우저 흐름 검사가 통과했는데 실제 녹음 스크린샷에서 기보 구조 오류가 드러났다.

**How to apply:** 실제 입력과 비슷한 비정박 시각의 각 prefix를 검사한다. 타이밍 오차가 작다는 이유로 표시 의미를 검증하지 않은 후보를 정상 기보로 채택하지 않는다.

타격 감지·간격 저장 성공과 올바른 기보는 별도로 검증한다. 사용자가 “입력은 감지하고 간격도 인지하는데 악보에 기보를 똑바로 못하잖아”라고 정정했다.

기보 유사율은 사용자 연주 채점이 아니라 앱의 기보 검증을 위한 것이다. 악보에서 복원한 타격열과 원본 탭을 비교하고, 앱이 먼저 검증·보정한 초안을 제시한다. 사용자는 연주 의도나 애매한 해석만 확인하며 앱 계산 오류를 대신 해결하지 않는다.

**Why:** 사용자가 “연주의 의도나 애매한걸 물어봐야지 전체적인 앱의 계산이 틀리면 안되겠지?”라고 책임 범위를 명시했다.

**How to apply:** 악보 구조·시간 계산·표시/재생 일치는 내부 검증 대상으로 둔다. 유사율을 정답 확률로 취급하거나 사용자 확인으로 계산 오류를 정상 처리하지 않는다. 확인 상태와 실제 일치도는 별개로 유지한다.

검증용 악보 재생은 원본 타격 시각을 복사하지 않고 표시 음가·점·연음에서 독립적으로 복원한다. 화면 표시와 검증은 동일한 기보 의미를 사용해야 한다.

**Why:** 원본 타이밍을 재생에 몰래 재사용하면 잘못된 기보도 유사율 100%가 되어 검증이 무의미해진다. 꾸밈음은 정량 음표와 달리 원본만으로 의도를 확정할 수 없다.

**How to apply:** 구조 오류에는 확정 기능을 제공하지 않는다. 원본 보존·계산 검증·의도 확인을 분리하고, 실패는 미해결로 남긴다. 유사율 기준은 실제 연주 자료로 보정할 기준이지 정확도 보증이 아니다.

**Why:** 입력 저장 검사만으로는 연음 사이의 불필요한 미세 쉼표, 끝음 음가 불일치, 마디 경계 오해석, 실제 표시의 음표 높이 오류를 잡지 못했다.

**How to apply:** 정답을 아는 타격열로 음가·쉼표·연음·마디 위치를 비교하고 실제 렌더링도 확인한다. 저장된 좌표만 확인하지 말고 화면상의 음표 높이와 연결선도 검사한다. 기보 오류 신고를 입력 감지 문제로 바꾸어 해석하지 않는다.

예비박·메트로놈 클릭과 건반 화음은 독립된 출력 소유권을 유지한다.

**Why:** 단음 미리듣기 출력은 이전 음을 끊는 의미를 갖는다. 이를 공통 클릭으로 재사용하면 메트로놈 한 박이 연주 중인 화음을 끊을 수 있다.

**How to apply:** 공통 미리듣기를 재사용하기 전에 이전 출력 종료 동작을 확인하고, 클릭을 정지할 때 연주 출력까지 종료하지 않도록 검증한다.
