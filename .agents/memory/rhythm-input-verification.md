---
name: 리듬 입력과 클릭 검증
description: 리듬 입력의 실제 down/up 저장과 화음·메트로놈의 독립 출력 검증 원칙.
---

리듬 입력 검증은 패드의 표시·클릭 성공만으로 끝내지 않는다. 저장된 타격 개수, 실제 누름·뗌 시각, 여러 건반의 독립 release를 확인한다.

**Why:** 브라우저에서 녹음 버튼과 패드가 정상 표시되고 클릭 검사도 성공했지만 실제 타격 콜백이 실행되지 않는 경우가 있었다. 직접 responder 입력으로 바꾼 뒤 원본 타격과 길이를 저장하는 검사가 통과했다.

**How to apply:** 입력 컴포넌트를 바꾸면 실제 브라우저에서 원본 저장 내용까지 검사한다. 단음 미리듣기의 성공을 화음 입력 성공으로 간주하지 않는다.

타격 감지·간격 저장 성공과 올바른 기보는 별도로 검증한다. 사용자가 “입력은 감지하고 간격도 인지하는데 악보에 기보를 똑바로 못하잖아”라고 정정했다.

**Why:** 입력 저장 검사만으로는 연음 사이의 불필요한 미세 쉼표, 끝음 음가 불일치, 마디 경계 오해석, 실제 표시의 음표 높이 오류를 잡지 못했다.

**How to apply:** 정답을 아는 타격열로 음가·쉼표·연음·마디 위치를 비교하고 실제 렌더링도 확인한다. 저장된 좌표만 확인하지 말고 화면상의 음표 높이와 연결선도 검사한다. 기보 오류 신고를 입력 감지 문제로 바꾸어 해석하지 않는다.

예비박·메트로놈 클릭과 건반 화음은 독립된 출력 소유권을 유지한다.

**Why:** 단음 미리듣기 출력은 이전 음을 끊는 의미를 갖는다. 이를 공통 클릭으로 재사용하면 메트로놈 한 박이 연주 중인 화음을 끊을 수 있다.

**How to apply:** 공통 미리듣기를 재사용하기 전에 이전 출력 종료 동작을 확인하고, 클릭을 정지할 때 연주 출력까지 종료하지 않도록 검증한다.
